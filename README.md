# 1cmcp — MCP-сервер внутри 1С:Предприятие 7.7

Нативная внешняя компонента (VC6, как 1sqlite/1C++), которая поднимает в процессе 1cv7.exe
HTTP-сервер по протоколу **MCP** (Model Context Protocol, транспорт Streamable HTTP, ответы JSON).
ИИ-агент (Claude Code и др.) подключается к работающему сеансу 1С, сам получает список
возможностей (`tools/list`) и может выполнять код, ждать результат, читать окно сообщений и журнал.

Зависимостей нет: одна `1cmcp.dll` (Winsock из Windows, MFC42/MSVCRT, которые идут с 1С).

## Запуск в 1С

Достаточно загрузить компоненту (в глобальном модуле):

```
ЗагрузитьВнешнююКомпоненту(КаталогИБ() + "1cmcp.dll");
```

После загрузки в **Сервис → Параметры** появляется вкладка **«MCP-сервер»**: порт, адрес, токен
(«Сгенерировать», «Копировать токен»), разрешение выполнять код, автозапуск, состояние сервера,
кнопки «Запустить/Остановить» и «Копировать команду для Claude Code». Настройки хранятся в
`1cmcp.ini` **в каталоге пользователя** (`КаталогПользователя()`, например `<база>\Users\Al\`), так что
у каждого пользователя свои порт, токен и автозапуск; в базе без списка пользователей это каталог ИБ.
При первой загрузке файл создаётся со случайным токеном. Общий `1cmcp.ini` из каталога ИБ (так
хранили версии до 0.3) забирает себе первый пользователь, загрузивший компоненту: файл копируется
в его каталог, а общий переименовывается в `1cmcp.ini.old`; остальные получают свои настройки.
С флажком «Запускать сервер при загрузке компоненты» больше ничего писать не нужно.
Если сервер запущен из кода с другими параметрами (`Запустить(18777, "...")`), вкладка это
показывает в «Состоянии» (порт, адрес, «другой токен»), а «Копировать команду для Claude Code»
берёт адрес и токен работающего сервера; поля страницы применятся при перезапуске.

Управление из кода (объект держать в переменной, пока нужен сервер):

```
глMCP = СоздатьОбъект("MCPСервер");
Если глMCP.Запустить() = 0 Тогда            // параметры из 1cmcp.ini
    Сообщить(глMCP.ПоследняяОшибка());
КонецЕсли;
```

Методы `MCPСервер` (англ. `MCPServer`):

| Метод | Описание |
|---|---|
| `Запустить(Порт, Токен, Адрес, РазрешитьКод)` | 1 — сервер запущен. Не заданные параметры берутся из `1cmcp.ini`. Без токена (или с токеном короче 16 символов) сервер не запускается |
| `Остановить()` | остановить сервер |
| `Работает()`, `Адрес()`, `ЧислоЗапросов()`, `Версия()`, `ПоследняяОшибка()` | состояние |
| `СгенерироватьТокен()` | случайный токен (48 hex) |
| `ФайлНастроек()` | путь к `1cmcp.ini` текущего пользователя |
| `ВыполнитьИнструмент(Имя, АргументыJSON)` | вызвать инструмент MCP из 1С (для отладки) |

Страница добавляется так же, как у FormEx: фабрика класса регистрируется только в процессе
(`CoRegisterClassObject`, реестр не трогается), а окну параметров передаётся CLSID через
`CAppFrame::m_OlePropertyPageSite.AddPropertyPage(CLSID, NULL)` — см. `src\optpage.cpp`.

Справка для синтакс-помощника Конфигуратора — [1cmcp.als](1cmcp.als) (положить рядом с `1cmcp.dll`
в каталог `BIN`). Она собирается скриптом `python docs/make_als.py` из текстов внутри него.

## Подключение Claude Code

Команду с адресом и токеном копирует кнопка на вкладке «MCP-сервер»:

```bash
claude mcp add --transport http 1c http://127.0.0.1:8777/mcp --header "Authorization: Bearer <токен из 1cmcp.ini>"
```

## Инструменты MCP

| Инструмент | Где выполняется | Назначение |
|---|---|---|
| `status` | сразу | свободна/занята, модальное окно, строка состояния, очередь |
| `screen` | сразу | окна процесса 1С, открытые формы, тексты и кнопки модального окна |
| `read_log` | сразу | хвост `SYSLOG\1cv7.mlg` с фильтром |
| `get_task` | сразу | результат долгой задачи |
| `dialog_button` | сразу | нажать кнопку в модальном окне (OK/Да/Нет…) |
| `eval` | главный поток 1С | вычислить выражение |
| `run_code` | главный поток 1С | выполнить фрагмент модуля, вернуть `Результат`, ошибки и новые сообщения |
| `read_messages` / `clear_messages` | главный поток 1С | окно сообщений |
| `forms` | главный поток 1С | открытые формы: вид, полный тип (`Справочник.Товары.ФормаСписка`), файл .ert, режим выбора |
| `form_controls` | главный поток 1С | элементы формы: id, вид, идентификатор, надпись, формула, слой, видимость, значение |
| `press_button` | главный поток 1С | нажать кнопку или флажок формы (по идентификатору, надписи или id) |
| `system_command` | главный поток 1С | команда меню по коду WM_COMMAND, список кодов — [docs/system_commands.md](docs/system_commands.md) |
| `metadata` | главный поток 1С | структура конфигурации из `Метаданные`: обзор, список вида, реквизиты объекта |
| `call_form_procedure` | главный поток 1С | вызвать процедуру/функцию модуля открытой формы по имени, в том числе без `Экспорт` |
| `read_table` | главный поток 1С | текст ячеек открытого табличного документа (результат отчёта, печатная форма) по строкам, частями |

`run_code` с параметром `form` выполняет код в контексте открытой формы, как будто он написан в её
модуле: реквизиты формы и `Форма` доступны по имени (`Вариант = "Остатки"; Форма.кнВыполнить.Доступность(1)`),
экспортные процедуры модуля формы и глобального модуля — тоже по имени (дружественным модулем
становится модуль формы, а у него дружественный — глобальный). Слово `Контекст` там не работает.
Процедуры формы без `Экспорт` вызывает `call_form_procedure` (как 1С++ `ВыполняемыйМодуль`:
`GetProcInfo` + `CallAsProc/CallAsFunc` модуля `CGetDoc7::m_pBLModule`).

Пример — отчёт «ПроизвольныйЗапрос» без сигнальных файлов: `run_code` открывает .ert (`ОткрытьФорму`),
`run_code` с `form` ставит `Вариант = "..."`, `call_form_procedure` `ЗагрузитьВариант`, `press_button`
«Выполнить запрос», затем `forms` находит окно результата и `read_table` читает его.

`read_table` читает ячейки прямо из `CSheetDoc::m_Sheet` (`LookupCell` + `CSheetCell::GetText`) — то,
что видит пользователь; строки и колонки в ответе нумеруются с 1, как R1C1.

Работа с формами устроена как у FormEx (`Сервис.СписокВсехОткрытыхОкон`, `РасширениеФормы.ТипОбъекта`):
MDI-окна главного фрейма → `CGetDoc7` → групповой контекст и тип по контейнеру метаданных.
Элементы формы берутся из `CGetDoc7::m_ControlList`: там идентификатор, надпись и формула, а
id совпадает с окном Windows уже в работающей форме (в Dialog Stream файла .ert id другие — 1С
перенумеровывает элементы при открытии). Нажатие — `BM_CLICK` по окну кнопки: 1С видит обычный
щелчок и выполняет формулу внутри вызова, поэтому ошибки и сообщения формулы приходят в ответе.
Код инструмента `metadata` — текст на языке 1С ([src/metadata.1c](src/metadata.1c)), вшит в DLL ресурсом.

1С однопоточная: запросы к ней выполняются по одному. Если задача не уложилась в `wait_seconds`
(по умолчанию 30 с) или внутри неё открылось модальное окно, возвращается `task_id`. Если задачу
держит модальное окно, в том же ответе сразу приходят `modal_window` (текст окна) и `buttons`
(точные названия кнопок): агент закрывает окно через `dialog_button` и забирает результат `get_task`.
В журнале вызовов такая задача помечается `PENDING`.

## Безопасность

- по умолчанию слушает только `127.0.0.1`; для удалённого доступа — SSH-туннель;
- токен `Authorization: Bearer …` обязателен всегда, даже на `127.0.0.1`: не короче 16 символов, латиница/цифры/знаки
  без пробелов (сгенерированный — 48 hex); сравнение за постоянное время, пауза при неверном токене;
  страница настроек не сохраняет настройки с пустым или слабым токеном;
- запросы с чужим `Origin` отклоняются (защита от DNS-rebinding из браузера);
- `РазрешитьКод=0` убирает `eval`/`run_code`, а также `press_button`/`system_command`/`call_form_procedure`
  (кнопка, команда или процедура может сделать всё, что пользователь); чтение (`forms`, `form_controls`,
  `metadata`, `read_table`) остаётся;
- журнал вызовов: `SYSLOG\1cmcp.log` в каталоге ИБ.

## Сборка и тесты

```bash
powershell -NoProfile -File build.ps1
```

- `build\selftest.exe` — тест ядра без 1С (HTTP, токен, MCP, очередь задач, журнал);
- `1CTestBase\run_mcp.ps1` — запуск тест-базы: обработка `Автотест.ert` (модуль
  `test\autotest_module.txt`) поднимает сервер, затем `test\mcp_client_test.py` проверяет его снаружи,
  включая сценарий «модальное окно внутри задачи». Глобальный модуль тест-базы открывает
  `Тест 1SQLite.ert` (имя зашито в MD, MD не правим) — это только пускатель
  (`test\launcher_module.txt`), он открывает `Автотест.ert`. Упаковка модуля:
  `python ert_module.py set Автотест.ert ..\test\autotest_module.txt`.
- `test\forms_test.py` (запускается тем же `run_mcp.ps1` вторым) — формы на тест-базе: `forms`,
  `form_controls`, нажатие кнопки и флажка, код в контексте формы, `system_command` с модальным
  диалогом, `metadata`; `VK\1duckdb\ClinicTest\clinic_1cmcp_metadata.py` — `metadata` на большой
  конфигурации через OLE (`run_py.ps1 -Script clinic_1cmcp_metadata.py`);
- `python docs/extract_commands.py` пересобирает [docs/system_commands.md](docs/system_commands.md) из
  ресурсов DLL платформы в `BIN` (меню, клавиши, подсказки строки состояния; нужен `pefile`) и из
  меню, снятых с работающей 1С (`docs/menus_live.json`): так у каждой команды указан режим
  (Предприятие / Конфигуратор / Монитор) и источник (DLL и номер меню-ресурса). Меню снимает
  `python docs/menu_dump.py <pid> <метка> docs/menus_live.json` — с тест-базы в каждом режиме и с копии
  Clinic через OLE (`VK\1duckdb\ClinicTest\clinic_menus.py`: документ, журналы);
- `1CTestBase\run_mcp.ps1 -NoClient -Keep` оставляет тестовую 1С с сервером работать (для ручной
  проверки или Claude Code), `run_mcp.ps1 -Stop` её закрывает. Скрипт закрывает **только** процессы
  1С, запущенные на этой тест-базе (по командной строке); другие открытые сеансы 1С не трогаются.
- `test\page_test.py <снимок.png> <путь к 1cmcp.ini>` — при запущенной тест-базе открывает
  «Сервис → Параметры», переходит на вкладку «MCP-сервер», делает снимок окна, меняет порт и токен,
  нажимает «Применить» и проверяет `1cmcp.ini` и перезапуск сервера.

## Структура

- `core\mcp_version.h` — **единственное место с версией**: из него её берут MCP (`serverInfo`,
  `status`), `Версия()`, вкладка настроек, ресурс версии DLL и `docs\make_als.py`;
- `core\` — JSON, HTTP-сервер на Winsock, MCP, очередь задач (UTF-8, без MFC и 1С);
- `src\` — компонента 1С: служебное окно в главном потоке, выполнение модуля, окно сообщений,
  страница настроек `optpage.cpp` (CP1251);
- `test\` — selftest, модуль для 1С, клиент MCP и тест страницы на Python.
